# 交叉编译与部署踩坑记录

按发现顺序记录。每条包含：现象 → 根因 → 修复 → 验证。

---

## 0. 路径必须是"真目录"而不是符号链接

**现象**：Chromium 的 `generate_shim_headers.py` 报
`PermissionError: '/home/.../qtwebengine/src/pdf/Release/aarch64/gen/../../../../../../../../../../../home'`

**根因**：`/home/yuanzingo/qt653-src`、`qt653-build` 用符号链接指向大容量盘时，
脚本里的 `..` 会被内核按**链接目标**解析，路径穿越到 `/home` 而不是预期位置。

**修复**：改用 **bind mount**，路径恢复真实层级：

```bash
sudo mkdir -p /home/yuanzingo/qt653-build
sudo mount --bind /data/work/qt653-build /home/yuanzingo/qt653-build
```
（重启后需重新挂载；symlink 只适合纯读取场景。）

## 1. `__isoc23_*` 未定义 + GLIBC_2.38 版本需求

**现象**（两个阶段）：
- 链接 `libQt6WebEngineCore.so` 时大量
  `undefined reference to __isoc23_strtol / __isoc23_sscanf / __isoc23_strtoul ...`
- 部署到 Pi 后 `ldd` 报
  `/lib/aarch64-linux-gnu/libc.so.6: version 'GLIBC_2.38' not found`

**根因**：宿主交叉 gcc 的内置搜索路径 `/usr/aarch64-linux-gnu/include` 与
`/usr/aarch64-linux-gnu/lib`（Ubuntu 24.04，glibc 2.39）排在 `--sysroot`
（Pi 的 glibc 2.36）**之前**。于是：
- C++ 编译时 `strtol/sscanf` 被 glibc 2.39 头文件重定向成 `__isoc23_*`
- 链接时又用了宿主的 `libc/libm`，把 `GLIBC_2.38` 需求写进了 `.gnu.version_r`

注意 `-I<sysroot>/usr/include` **无效**：GCC 会判定它与系统目录重复而忽略。

**修复**（两层）：
1. **头文件侧**：写 `cross-build/isoc23_compat.c`，把 7 个 `__isoc23_*`
   映射到 2.36 的同名函数，编译成 `.o` 注入所有链接命令。
2. **库侧**：在链接命令里显式加
   `-L<sysroot>/usr/lib/aarch64-linux-gnu -L<sysroot>/lib/aarch64-linux-gnu`
   （`-L` 优先于内置路径），使 `.gnu.version_r` 只记录 ≤ 2.35。

**注入位置**（`cross-build/patch-qt-build.py` 自动处理，幂等）：
- `qt653-build/CMakeFiles/rules.ninja` 里所有 `*LINKER*` rule 的 `command`
- `qt653-build/qtwebengine/src/{core,pdf}/Release/aarch64/toolchain.ninja`
  的 `rspfile_content`
- 项目侧通过 `toolchain-pi653.cmake` 的 `CMAKE_*_LINKER_FLAGS_INIT`

**验证**：`objdump -T <elf> | grep -oE 'GLIBC_2\.[0-9]+' | sort -V | tail -1` → ≤ 2.35。

## 2. Qt 没编译 xcb 平台插件

**现象**：Pi（X11 会话）上启动报
`Could not find the Qt platform plugin "xcb"`，
可用插件只有 `vnc/offscreen/minimal/linuxfb/minimalegl/eglfs/vkkhrdisplay`。

**根因**：`CMakeCache.txt` 里 `FEATURE_xcb:OFF`。sysroot 中 xcb 扩展只有运行时
`.so.0`，缺 `.so` 开发链接、缺 `xkbcommon-x11.h/.pc`、缺 `xproto.pc` 与
`pthread-stubs.pc`，配置阶段判定不可用。

**修复**：
1. 从 Debian 12 arm64 仓库下载 14 个 dev 包装进 sysroot
   （清单见 `cross-build/README.md` 2.1）。
2. **另建一个只含 qtbase 的构建树** `qt653-build-xcb`，`-DFEATURE_xcb=ON` 编出
   `libqxcb.so` + `libQt6XcbQpa.so.6.5.3`。
   这样做是为了**不动主构建树**——重新 configure 主树可能触发
   QtWebEngine 的 GN 重生成，导致 Chromium 全量重编。

## 3. xcb 插件加载失败：`QX11Application` typeinfo 缺失

**现象**：
```
libQt6XcbQpa.so.6: undefined symbol: _ZTIN16QNativeInterface15QX11ApplicationE, version Qt_6
```

**根因**：安装树里的 `libQt6Gui.so` 是在 `FEATURE_xcb=OFF` 时构建的，
条件编译掉了 `QNativeInterface::QX11Application` 的 typeinfo/vtable。

**修复**：用 `qt653-build-xcb` 产出的 Gui 替换。替换前做了符号差集校验
（旧 Gui 的符号在新 Gui 中缺失数为 **0**），确认二进制兼容后才替换。

## 4. `Cannot create platform OpenGL context, neither GLX nor EGL are enabled`

**现象**：xcb 插件能加载，但 OpenGL 上下文创建失败，QML 窗口不显示。

**根因**：`libqxcb-egl-integration.so` 没装到 `plugins/xcbglintegrations/`。
只装了 `plugins/platforms/libqxcb.so` 不够。

**修复**：从 `qt653-build-xcb/plugins/xcbglintegrations/` 复制并修正 RUNPATH 为
`$ORIGIN/../../lib`。

## 5. 部署细节坑

| 现象 | 处理 |
| :--- | :--- |
| `tar -xzf` 报 `not in gzip format` | 包是 zstd，用 `tar -xf`（GNU tar ≥ 1.31 自动识别）|
| `cp: cannot create ... Text file busy` | 先 `systemctl stop orange-pi-net-proxy orange-pi-file-daemon` |
| `orange-pi-file-daemon` 226/NAMESPACE → 后变 `cannot read token file` | token 由主程序启动时生成；首次向导完成前该 unit 重启失败属预期 |
| qmake wrapper 指向 `/opt/Qt/6.5.3/gcc_64/bin/qmake6` | 交叉构建的 qmake 是宿主 wrapper，Pi 上不可用；构建走 cmake，不影响运行 |
| `scrot` 截图全黑 | 显示栈是 wlroots(Wayland)+Xwayland，root 窗口无内容；用 `import -window <id>` 抓应用窗口 |

## 6. 安全配置修正

原服务 drop-in 里有 `Environment=QTWEBENGINE_DISABLE_SANDBOX=1`，会关闭 Chromium 沙箱。
新 drop-in 用 `UnsetEnvironment=QTWEBENGINE_DISABLE_SANDBOX` 移除；
实测进程环境无该变量、`QtWebEngineProcess` 无 `--no-sandbox`。

同时核验 systemd 沙箱属性（`ProtectSystem=strict`、`ProtectHome`、`PrivateTmp`、
`NoNewPrivileges`、`RestrictNamespaces`、`MemoryDenyWriteExecute`、`DynamicUser`）全部生效。
