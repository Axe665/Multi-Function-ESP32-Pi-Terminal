# 天气与天气设置：按 Windows / GNOME / Android 重做（2026-11-01）

> 范围：`WeatherTools.qml`（天气主页）与 `WeatherSettings.qml`（右上角齿轮的设置层）。
> 只改界面；数据源、缓存、单位与请求仍归 `WeatherEngine.qml`。

## 1. 天气主页

1. **四项指标改成 2×2 小卡**：体感 / 湿度 / 风速 / 降水概率，每格带图标、
   标签和值，卡片用 `surfaceContainer + outlineVariant`，和设置页的分组同一语言。
2. **未来 7 天加温度条**（Windows 天气的写法）：以本周最低/最高为基准，
   每天画一条「低温—高温」区间条，长度与位置直接表达冷暖；
   行结构变成 日期 / 月日 / 图标 / 低温 / 温度条 / 高温 / 降水概率。
3. **高度分配**：24 小时卡 190→160，7 天卡 300→240，1024×600 下 7 天能完整显示三行，
   不再被窗口裁掉第一行。
4. 24 小时横向条、地点切换、播报、刷新、设置齿轮的 objectName 全部未动
   （`weatherCurrentPane`、`weatherTemperature`、`weatherHourlyStrip` 等）。

## 2. 天气设置

数据源从「一行挤五个控件」改成两行：

```
Open-Meteo                          已启用  [开关]
                          上移  下移  测试
──────────────────────────────────────────────
```

- 第一行：名称（可省略）+ 状态 + 开关；
- 第二行：右对齐的排序与测试按钮；
- 源与源之间加发丝线。
- 其余分组（OpenWeather、自定义 API、MET Norway、刷新与单位）结构不变。

## 3. 设计取向

- 颜色不新增：天气用现有 `#35a9ff`，预报 `#4fd4a4`，温度条用 `Theme.accent`；
- 温度数字仍是全页最大的元素，温度条是唯一新增的视觉语法；
- 不加渐变背景、不做逐卡入场动画——车机上扫读优先。

## 4. 验证

- `weather_tools_test` 断言依赖的 objectName 与温度文本保留；
- 1024×600 实机截图：`weather-home.png`、`weather-settings.png`。

## 5. 第二轮修复（同日，按反馈）

1. **24 小时卡文字压框**：卡片高度回到 190，横向条 104→92，降水概率行回到卡内。
2. **底部圆角被裁**：
   - `TimePane` 的底部渐隐条缩到一格高并向内缩一个圆角半径，不再用直角矩形盖住圆角；
   - 天气页内容末尾加一格占位，整页可滚动（`contentHeight = max(视口, 内容)`）——
     1024×600 下滚到底时两张卡的底部圆角完整可见；
   - 双栏 GridLayout 加 `Layout.bottomMargin`。
3. **天气设置比例**：数据源名称从 `Theme.body` 升到 `Theme.fontStrong`（并显式前景色），
   上移/下移/测试三个按钮降到 `Theme.fontLabel`，不再出现"名字小、按钮大"的失衡。

## 6. 滑动隔离（同日）

双栏时外层 Flickable 的 `contentHeight` 固定等于视口，整页不再跟手：

- 在「未来 7 天」或「实况」卡上拖动，只滚该卡内部的 Flickable，页面本身不动；
- 窄屏单栏仍保持整页滚动（原行为）；
- Loader 高度 = `视口 - 一格`，卡片底部不贴页面边缘。
