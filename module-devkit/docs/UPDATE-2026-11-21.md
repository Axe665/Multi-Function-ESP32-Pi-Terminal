# 2026-11-21 更新说明

> 本文件是模块 SDK 的更新说明。仓库路径已归到根 `esp/`；模块 SDK 基线是 Qt 6.5.3 / API v3，
> 仓库里的 `pi_terminal` 宿源码仍在开发中（v2），同步前只能离线验收。

这一版把模块开发工具链对齐到当前项目进度。**如果你之前拿过旧 SDK，请整体替换，不要只拷单个文件**——
`pi_module_sdk.h`、模板和工具链之间有配合关系。

## 最重要的变化：Qt 6.5.3

模块 SDK 基线是 **Qt 6.5.3**，6.4.x 已不支持。模板与所有示例的 `CMakeLists.txt` 都写
`find_package(Qt6 6.5 REQUIRED COMPONENTS Core)`，低于 6.5 直接配置失败——**不要**为了编过把门槛调低。

**不要用板端系统 Qt 编模块。** 那块板子上的发行版 Qt 是 6.4.2，用它编出来的 `.so` 与宿主的
6.5.3 运行时不匹配，症状是模块加载失败或运行时找不到符号，而报错现场离构建很远。

## 新增：交叉编译工具链

```sh
cmake -S my-module -B build \
  -DMODULE_SDK_DIR="$PWD/sdk" \
  -DCMAKE_TOOLCHAIN_FILE="$PWD/toolchain/module-aarch64.cmake"
```

`toolchain/module-aarch64.cmake` 会自动探测三件套（Qt 6.5.3 aarch64 / 宿主 Qt / Debian 12 sysroot）：

1. 环境变量 `ORPI_QT_PREFIX`、`ORPI_HOST_QT`、`ORPI_SYSROOT`；
2. `<devkit>/dist/sdk/`，以及从 devkit 向上逐层查找的 `dist/sdk/`。

找不到会直接 `FATAL_ERROR` 并告诉你缺哪个，不会静默降级去用系统 Qt。

它做对了两件容易被忽略的事：

- **不写 RUNPATH**。CMake 交叉编译默认把 Qt 的绝对路径写进产物，模块在目标机上按那条路径
  找不到 Qt。`release` 之后还会再检查一遍，带绝对路径的产物会被拒绝。
- **`isoc23` 兼容桩**。宿主交叉包的 glibc 是 2.39、sysroot 是 2.36，不补桩时产物会记录
  `GLIBC_2.38` 需求，在目标板上报 `version 'GLIBC_2.38' not found`。

## 新增：SDK 补齐了 v2/v3 的宿主能力

`pi_module_sdk.h` 从 4 个封装扩到 10 个。之前只有 `send_json` / `publish` / `log` / `valid`，
而宿主实际实现了 9 个回调，`network_request`、`file_request`、`data_directory`、`send_control`
一个封装都没有：

```cpp
pi_module_sdk::network_request(host, R"({"method":"GET","url":"https://..."})");
pi_module_sdk::file_request(host, R"({"op":"read","path":"..."})");
pi_module_sdk::data_directory(host);
pi_module_sdk::has_network(host);   // 老宿主的函数指针可能是空的，先探测
```

模块页面侧新增/确认了这些注入项（详见 `docs/AI-CODING-GUIDE.md` 的「宿主能提供什么」）：

| 注入项 | 用途 |
| --- | --- |
| `appData` | 数据接口（v3 名称；`moduleData` 是兼容别名，保留一个版本周期） |
| `appAdvice` | 建议通道：`setModuleId` + `request({record, windowMs})`，异步回 `adviceReady`/`adviceFailed` |
| `appNetwork` | **异步** HTTP(S)：`request` 返回 id，结果走 `finished(id, response)` |
| `appFiles` | 受控文件；写权限要先 `requestWriteAccess()` |
| `sessionModel` / `userContext` / `hostTheme` | 会话 / 用户 / 主题 |

注意 C++ 的 `network_request` 是**同步阻塞**（最长 35 s），QML 的 `appNetwork.request` 才是异步的；
两者的返回值都只活到下一次调用。

## 新增：接好新 API 的通用 QML 页面

`template/qml/ModulePage.qml` 换成了参照智能花盘结构、**不写死任何颜色**的通用页面：
建议入口卡 → 标题行 → Hero 卡（主视觉插槽）→ 指标网格 → 页脚，外加右滑建议页。

它已经接好全部新接口：

- `appData.query(record, {limit:1})` 定时取最近一行，用 `received_at` 判在线（15 s 余量）；
- `appAdvice` 完整状态机，`adviceReady` 的 `payload` 是 `{items:[{text,risk}], source}`；
- 指标网格列数随指标数量自适应（宽屏最多 4 列、窄屏 2 列）。

**颜色全部从 `hostTheme` 派生**（宿主只给 `background`/`surface`/`foreground`/`accent`/`scale`
五个令牌），卡片层次用 `veil(alpha)`、`accentVeil(alpha)` 叠前景色得到。好处是同一份页面
在浅色与深色主题下都成立，你不需要为别人改的主题再调一遍色。

新模块主要改文件顶部「模块配置」：`kicker`、`headline`、`heroNote`、`sampleRecord`
（换成自己 `data_schema` 里的记录名）、`metrics`、可选的 `heroVisual`。

## 新增：模板自带测试骨架

```sh
cmake -S my-module -B test-build -DMODULE_SDK_DIR="$PWD/sdk" \
  -DMODULE_TESTING=ON -DCMAKE_PREFIX_PATH=/path/to/Qt/6.5.3/gcc_64
cmake --build test-build --parallel
ctest --test-dir test-build --output-on-failure
```

不需要真机、不需要装模块。真机上出现「页面没数据」时，先跑它能区分是模块没发还是宿主没接。

## `module_devkit.py` 的变化

- `doctor` 增加 aarch64 交叉编译一节：编译器、工具链、Qt、sysroot 逐项报 OK/MISSING；
- `release --arch aarch64` 不传 `--toolchain` 时默认用自带工具链，不再要求手写路径；
- 新增产物 RUNPATH 检查，带开发机绝对路径的 `.so` 直接拒绝打包；
- 三件套探测支持三种 devkit 落点（仓库根、SDK 快照副本、独立目录）。

## 已知问题

- 若你自己维护的 toolchain 文件用 `string(APPEND CMAKE_*_LINKER_FLAGS_INIT ...)` 注入 isoc23 桩，
  会因为 toolchain 在 configure 期间被求值两次而**注入两遍**，链接报
  `multiple definition of __isoc23_strtol`。用 `set` 而不是 `APPEND`。
- 上游 2026-11-21 包**不含** `artifacts/`；本仓库仍保留 v2 历史签名包，见 `artifacts/README.md`，不能装到 v3 宿主。
