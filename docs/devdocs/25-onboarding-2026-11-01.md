# 首次开机向导（OOBE，2026-11-01）

> 目标：设备内一个用户都没有时，不再让登录页显示“请先在终端执行 --init-admin”，
> 而是在进入登录界面前走一遍五步向导，创建首个管理员并直接进入桌面。
> 本轮只做主流程与契约测试；实机触摸/键盘层级仍待现场验收。

## 1. 触发与边界

- 判定只有一条：`UserService::hasAnyUser() == false`，且没有调试豁免。
  在 `TerminalApplication::initialize()` 里算一次，之后不再变化。
- 删光所有用户后，下次启动自然重新进入向导（不需要额外标记文件）；
  运行中删掉最后一个用户则由 `OnboardingController::rearm()` 立即重入，
  见 [27-last-admin-self-delete-2026-11-01.md](27-last-admin-self-delete-2026-11-01.md)。
- 向导激活时 `SessionGate` 让位（`enabledGate` 加上 `!onboarding.active`），
  否则登录页会在底下渲染并抢焦点。
- 与命令行初始化的关系：`--init-admin` 保留为无头/救援路径，两者都走
  `UserService::createInitialAdmin`，不存在第二套创建逻辑。
- `ONBOARDING` 不参与联网：网络步骤只读 `QNetworkInterface`，不发任何包。

## 2. 五步流程

| 步 | 内容 | 关键约束 |
| :--- | :--- | :--- |
| 1 | 欢迎 + 语言（中文/English） | 写全局 `uiLanguage`，向导与桌面同步；不可返回 |
| 2 | 管理员显示名 + 6 位 PIN（两次） | 名字 2–24 字符，默认“管理员”；PIN 复用 `PinPad`，两次不一致留在本页 |
| 3 | 恢复码（一次性展示 + 抄写确认） | 24 字符分 6 组、等宽大字号；要求输入第 2、5 组；**此步生成恢复码，但尚未写盘** |
| 4 | 网络（只读状态 + 重新检测） | 可跳过；不提供 Wi-Fi 密码输入，联网留到桌面设置 |
| 5 | 完成 | 点“完成设置”才调用 `createInitialAdmin`；成功后按钮变“进入桌面”，由用户决定何时切换 |

导航：可返回上一步；恢复码确认后 PIN 步不再回退；创建成功后整轮锁定。
进度：顶部线性条 + “第 n 步，共 5 步”。

## 3. 落盘顺序（为什么先展示恢复码）

现有命令行流程是“先 `createInitialAdmin`、再打印恢复码”。GUI 照搬会有一个死局：
用户在恢复码还没抄完时断电/退出，重启后注册表已非空、向导不再出现，恢复码永久丢失。

所以向导反过来：

1. 进入第 3 步时 `OnboardingController::prepareRecoveryCode()` 生成并展示；
2. 用户输入第 2、5 组确认抄写；
3. 第 5 步点击“完成设置”才调用 `createInitialAdmin(name, pin, recoveryCode)`；
4. 成功后立刻 `SessionManager::login(userId, pin)`，直接进桌面。

中途任何一步退出都不留文件（注册表在最后一步才写）。

## 4. 实现

| 文件 | 职责 |
| :--- | :--- |
| `src/app/OnboardingController.h/.cpp` | `active/ready/busy/recoveryCode/errorCode/network*`；恢复码生成与确认、创建管理员、自动登录、网络接口探测 |
| `qml/onboarding/OnboardingWizard.qml` | 步骤编排、进度、底部按钮、电源确认、向导自己的键盘实例 |
| `qml/onboarding/WelcomeStep.qml` 等五步 + `ProgressHeader.qml` | 每步一个文件 |
| `qml/Main.qml` | `Overlay.overlay` 上新增 Loader（z=50000，`startupComplete` 后加载）；SessionGate 让位 |
| `src/app/TerminalApplication.cpp` | 计算 `onboardingRequired`，注入 `onboarding` 上下文属性 |
| `src/app/TerminalOptions.cpp` | 新增 `--skip-onboarding`（仅调试） |
| `qml/PinPad.qml` | 新增 `placeholderText` / `busyText`，默认值保持登录语义 |
| `tests/onboarding_test.cpp` | 5 个契约用例（触发、恢复码分组/幂等、抄写校验、非法输入、创建落盘） |

错误码到文案的映射在 `DoneStep.qml`：`name_invalid`、`pin_mismatch`、`pin_invalid`、
`create_failed`、`login_failed`；恢复码错误码是 `recovery_mismatch`（显示在 `RecoveryStep`）。
所有错误内联显示，不弹模态层。

## 5. 调试豁免

`--ui-test`、`--no-login`、`--skip-onboarding` 跳过向导，并打印
`onboarding: bypassed by debug flag, user registry is empty`。
`--ui-audit` 的干净 XDG 环境会预建管理员，因此本来就不会进入向导。
生产环境不要设置这些开关。

## 6. 验证状态（2026-11-01，x86_64 + Xvfb）

### 6.1 构建环境（按作者方案现装）

- **Qt 6.5.3 作者 SDK**：`$HOME/.local/share/orange-pi-terminal-sdk/qt/6.5.3/gcc_64`
  （aqtinstall 3.3.0 + 阿里云镜像）。注意作者 `scripts/setup-desktop.py`
  的模块表漏了 `qtmultimedia`，CMake 会在第一个 `find_package(Qt6)` 失败，
  需要补 `aqt install-qt ... -m qtmultimedia`。
- **SQLCipher 4.5.6 / OpenSSL 3.0.13 / mbedtls 2.28.8**：`apt download` +
  `dpkg-deb -x` 到仓库外前缀（本机 `/home/yuanzingo/wark/.deps/root`），
  CMake 显式传 `SQLCIPHER_ROOT`、`OPENSSL_INCLUDE_DIR`、`OPENSSL_CRYPTO_LIBRARY`、
  `OPENSSL_SSL_LIBRARY`、`MBEDTLS_INCLUDE_DIR`、`MBEDTLS_CRYPTO_LIBRARY`。
- VLC 3.0.20 用系统 `libvlc-dev`（pkg-config 可用）；GStreamer 头来自
  `third_party/gst/amd64`，运行库用系统 1.24。
- 坑：缺 mbedtls 时项目**并不能**按文档“跳过 HostIdentity 照常构建”——
  `SecurityStatus.cpp` 的 `unique_ptr<HostIdentity>` 会报不完整类型。必须补 mbedtls。

```bash
source pi_terminal/scripts/env.sh
R=/home/yuanzingo/wark/.deps/root/usr
cmake -S pi_terminal -B /tmp/oobe-build -DCMAKE_BUILD_TYPE=Release \
  -DSQLCIPHER_ROOT=$R \
  -DOPENSSL_INCLUDE_DIR=$R/include \
  -DOPENSSL_CRYPTO_LIBRARY=$R/lib/x86_64-linux-gnu/libcrypto.so \
  -DOPENSSL_SSL_LIBRARY=$R/lib/x86_64-linux-gnu/libssl.so \
  -DMBEDTLS_INCLUDE_DIR=$R/include \
  -DMBEDTLS_CRYPTO_LIBRARY=$R/lib/x86_64-linux-gnu/libmbedcrypto.so
cmake --build /tmp/oobe-build --target orange_pi_terminal -j4
```

### 6.3 端到端（Xvfb 1024×600，空 XDG）

→ `04-recovery-mismatch`（故意输错）→ `05-network` → `06-done` → `07-ready`
→ `08-desktop`。

1. 启动日志 `onboarding: no users, starting first-run setup`；
2. 五步走完，恢复码页显示 6 组（如 `TBDG UWQT 2CRN / P5JM H4BD VQH4`）；
3. 输错第 2、5 组 → 红字“与恢复码不一致”，停留本步；
4. 改对 → 第 4 步显示真实接口 `wlo1 · 192.168.0.197`；
5. 点“完成设置” → 创建成功，按钮变“进入桌面”；
6. 点“进入桌面” → 桌面出现，SessionGate 未出现，日志 `auth: login completed in 655 ms`；
7. 同一 XDG 重启 → 登录页（“管理员” + 访客），**不再进向导**；
8. `users.json`：`schema=p0-users-v1`、`admin=true`、`display_name=管理员`、
   `has_recovery_code=true`。

### 6.4 端到端发现并修复的问题（均有截图复核）

1. **恢复码 6 组全空**：`recoveryGroup()` 是 `Q_INVOKABLE`，绑定不依赖
   `recoveryCode`，`prepareRecoveryCode()` 之后不会重算。改为显式依赖
   `onboarding.recoveryCode.length`。
2. **软键盘被向导盖住**：Popup 的 z 与 Overlay 下普通 item 同层比较，`z:1000`
   低于 OOBE Loader 的 50000；改为 51000。
3. **底部按钮落进软键盘区域**：全屏向导的纵向坐标误乘了 0.75 缩放，
   按钮被顶到 y=390；改为按屏幕高度贴底（`height - hit - margin`）。
4. **确认输入被键盘遮挡**：第 2/5 组输入框原本在恢复码下方（y≈300，
   键盘从 256 起）；改为与恢复码同一行。
5. **恢复码第二行被键盘压住**：字号 27→24、行距收紧。
6. **电源图标名不存在**：`power_settings_new` 不在图标资源里，回退成星形；
   改为 `power`。

## 7. 已知边界 / 未完成

1. 向导自己实例化的 `FloatingKeyboard` 用 `z: 51000` 压在 OOBE Loader（50000）
   之上，已在 Xvfb + Qt 6.5.3 实测可见；若目标机 Qt 行为不同，回退方案是把
   OOBE 的 Loader 降到 z=20000、键盘显式抬到 21000（与全局 screenKeyboard 同源）。
2. GuiAudit 的 OOBE 场景（5 步 + large-text）本轮未加，仍是待办。
3. 没有“恢复出厂”入口：按约定只做删光用户后的自然重入（运行中的最后一名用户自删见 27 号文档）。
4. 自动登录失败（例如库打不开）时，管理员已创建、向导关闭，用户下次走登录页；
   错误只进日志，不再弹窗。
