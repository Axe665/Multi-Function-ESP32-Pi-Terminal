# v2.3 文档与实现的差异

对照的是 `端边云技术方案-v2.3.docx` 的第 5、6、8、11 章与附录 B、C，
以及边仓 `Modular-Terminal-Edge`、云仓 `Modular-Terminal-Cloud` 当前的 main。

按「文档说法 → 实际实现 → 处置」记。已经改掉的在最后标注提交所在仓库。

## 一、会挂的

### 1. 边数据路径

- 文档 §5.1：`数据落在 /srv/modular-terminal-edge/data/edge.db`
- 实现：Docker 用命名卷 `edge_data:/app/data`；原生 `run.sh` 写仓库里的 `./data/edge.db`
- 后果：两套部署是两份库，切模式看到的是另一套数据；文档写的路径两边都不是
- 处置：compose 改成 `../data:/app/data`，容器 `user` 固定 1000，与原生共用同一个
  `edge.db`。已有部署的迁移命令写在边仓 README 的 Docker 段落

### 2. 443 把管理 API 和 Ollama 一起代理出境

- 文档 §6.1 / §8.3：公网只开 `edge-report` 与 `health`，管理台和 Ollama 仅内网
- 实现：compose 把 `80/443/8443` 发布到 `0.0.0.0`，443 站点 `handle /api/*` 全量反代、
  另有免鉴权的 `/ollama/*`；管理接口在「没配口令」时直接放行（`admin_guard` 的空档）
- 实测：同一网段 `https://<LAN IP>/api/v1/overview` 无凭据 200，`/health` 自报
  `admin_token: open`
- 处置：管理接口改成默认拒绝（没配口令/令牌就 403），演示要显式
  `CLOUD_DEMO_OPEN=1`；`/ollama/*` 移到只绑 `127.0.0.1` 的 8088，443 明确 403。云仓修复
- 后续（独立审计发现）：443 上仍可伪造 `X-Client-CN` 冒充边写入数据——Caddy 默认
  透传客户端自带的头，而 `edge_guard` 见到这个头就当已验签身份。现在 443 显式
  拒绝 `/api/v1/ingest/*` 并清掉该头，摄取只走 8443 的 mTLS。顺带补上按内网 IP
  访问 443 的两个缺口（站点地址没带 `CLOUD_LAN_IP`、浏览器对 IP 不发 SNI）

### 3. 本机 broker 配置写死了别人的路径

- 文档 §5.1：主机跑 Avahi 与 chrony，mqtt 由 compose 的 mosquitto 提供
- 实现：`docker/mosquitto/edge-local.conf` 里 `cafile`、`certfile`、`keyfile`、`acl_file`、
  `crlfile` 全部指向 `/home/yuanzingo/文档/deepseek-harness/...`，是另一台机器的绝对路径
- 后果：非容器部署（`scripts/install_systemd.sh` 那套）的 mqtt 在任何别的机器上都起不来；
  `install_systemd.sh` 只替换 `.service` 里的 `@ROOT@`，不处理这个 conf
- 处置：改成 `edge-local.conf.in` 模板，由 `install_systemd.sh` 生成
  `deploy/edge-mqtt.conf`（已 gitignore），systemd 单元指向生成的文件。边仓修复

## 二、口径不一致

### 3. 设备证书的「自动续期」

- 文档 §5.7 第 3 条、§0.2「证书续期」：设备证书到期前 30 天自动续期，续期失败告警
- 实现：边提供 `POST /api/v1/devices/{id}/renew` 给设备调用，调度器把 `expiring`
  记进审计和计数，页面提示。没有自动签发
- 原因：CSR 由设备生成，私钥不出端，边无法单方续签
- 处置：以实现为准。边负责 30 天内提醒和告警。**文档需改**
- 后续（独立审计发现）：这个接口原来只校验共享摄取令牌，而 `device_id` 由调用方
  指定——拿到令牌就能用自己的私钥换一张 `CN=任意设备` 的证书。现在提到管理员
  权限，所以「设备自行续期」这条路要改成运维侧代跑（或给设备单独发一个能签自己
  证书的凭据，尚未实现）

### 4. advice 载荷的 schema

- 文档 §5.2 表格：advice 主题的载荷「同上（可分离）」，即 `orpi.telemetry.v1`
- 文档附录 C：advice 主题的载荷是 `orpi.advice.v1`
- 实现：`contracts/wire/advice.v1.json` 存在，但 `edge/models.py` 里没有 advice 的
  校验模型，只有 telemetry、status、edge-report 三个
- 处置：以附录 C 为准（advice 有独立契约）。边目前不校验这个主题的载荷，属于
  缺口，记在这里不假装已实现

### 5. 云本地模型的名字

- 文档 §6.1、§6.3：Qwen3.5-9B q4
- 实现：`docker/compose.yml` 默认 `qwen3.5:9b`，但 `cloud/config.py` 默认 `qwen3.5`
- 后果：不用 compose、直接跑 `run.sh` 时模型名对不上，Ollama 找不到模型
- 处置：`config.py` 改成 `qwen3.5:9b`。云仓修复

### 6. 云的明文入口

- 文档 §6.1：Caddy 监听 443，用 cloud-ca 签发
- 实现：另有 `:8088` 明文入口，只绑 127.0.0.1，给本机调试和截图用
- 处置：不算冲突，补进文档即可

### 7. 云备份的落点

- 文档 §6.7：每日 pg_dump 到外接 USB 硬盘
- 实现：`CLOUD_BACKUP_DIR` 默认是仓库下的 `backups/`，USB 盘要靠环境变量指过去
- 处置：部署约定，不是代码错。文档补一句「默认落仓库目录，生产要把
  `CLOUD_BACKUP_DIR` 指到挂载的外接盘」

## 四、核对过、没问题的

边：MQTT 主题与 QoS、`batch_id = sha256(deviceId+from+to)[:16]`、配对码 6 位 10 分钟、
证书 365 天且 CN=deviceId / OU=mt-device、CRL、mDNS 三类服务与 TXT
字段、5 分钟入库与 24 小时按 15 分钟重采样、jieba 加停用词加 TF-IDF、每小时上云、
退避 1 分钟 / 5 分钟 / 30 分钟 / 2 小时、outbox 7 天过期、快照保留 7 天、k≥5、边保留 180 天。

云：表结构与附录 DDL 一致（多出 `module_id/label/unit/table_name` 等列）、管理员口令加 TOTP、
原始字段拒收并计数审计、k≥5 聚合、`(scope, period, prompt_hash)` 24 小时缓存、
输入 8k 裁剪、每日 03:00 备份保留 14 天、每月恢复演练、cgroup 2G/1G/1G+1G/8G、
公网只开 `edge-report` 与 `health`、网站六页齐全。

### 仍未做

- **§4.6.2 的「同一 subject×metric×1h 最多贡献 1 次」**：边侧的 `aggregates` 没有
  subject 维度，这条规则在现有表结构里没有落点。要么给聚合表加 subject 计数，
  要么承认由端侧保证
- **文本脱敏只有正则与固定词典**：姓氏 + 14 个地名，没有 NER，「王小明」「协和医院」
  这类拦不住。上 NER 意味着边要带模型，与内存预算冲突。云端加了同样的兜底，
  但两边都不是真脱敏
- **备份历史未重写**：旧的 17 份 dump 仍能从 git 历史里取到，只是不在当前树里
- **原始字段告警只到 API**：`/overview.alerts` 有这条系统级告警，但前端「待处理」
  列表读的是 `/alerts`（按设备聚合的结构），所以界面还看不到
- **`docker/mosquitto/certs/broker.key` 仍是 0644**：mosquitto 以非属主 uid 运行，
  收到 0600 就起不来。要根治得在 compose 里显式指定 mosquitto 的运行用户
- **改 `EDGE_ID` 要手工同步 `docker/mosquitto/acl`**：里面的用户名写死成
  `edge-lab-01`，还没模板化
- **端仓没有 `contracts/` 目录**：`contracts/wire/telemetry.v1.json` 尚未发布，
  边仓那份 vendor 副本仍是「代管 + 示例」。端仓发版后要换成 tag 拉取
- **真机项未验证**：CRL 重载后已连设备是否 1 分钟内断开、宿主 Avahi 是否真的
  在局域网可发现、恢复演练 RTO 只在本机测过
