端-边-云架构（端包括硬件层以及软件层 即pi终端 边-一种管理软件 云-云服务器（私有网站+ai分析模型（用户隐私考虑）））
端需要改造：
1.明确数据格式：修改模块权限列表（json） 在里面加入明确的数据格式（比如说血氧血压模块的数据格式为用户名-血氧值-血压值-等等） 改造Database API每次与模块握手时读取json文件确定数据格式 模块QML页面申请DB API时DB API只允许QML页面读取和写入(R+W)模块自己声明的数据格式 其他的一律拒绝 同步这个更改到模块开发SDK中
2.新增系统底层服务HyperVisor 接入系统File API以及DB api 提供user-side（一种上报文类API 向模块页面QML提供用户个性化建议 数据格式为模块id+不同用户id+建议 QML页面可以接入）和server-side（向上层架构边上报）HyperVisor分为两层（分别为过滤层以及模型层） 过滤层包含一个算法负责分出不同用户旗下的数据（做成用户+用户一系列数据集的形式） 简单来说就是使用DB API以及File API(R+W) 分出不同用户数据（方便给下一层模型层 用来给用户个性化建议以及方便分析） 模型层是混合架构（model API（接入网络控制系统）+本地私有小模型的形式（按需启用）） 负责接受过滤层的数据并提供个性化建议以及上报给server-side 模型层工作分为两种情况：1.有网络 2.无网络 有网情况下user-side端数据汇报为过滤层接受->本地私有模型分析不同类别数据的变化趋势（保存用户id,但是汇报给下一环节要做数据去敏）->把趋势汇报给model API ->把返回值加用户id+模块id 回报给模块页面请求API）无网情况下user-side端不需要做敏感数据去敏 本地私有模型同时分析数据变化趋势以及为用户提供个性化建议 
Server-side负责上报给边客户端（本地局域网架构（无网）或者私有服务器（有网）） 数据处理方式和user-side差不多 但是处理的是所有用户数据的集合（需要做敏感数据脱敏） 有网情况下直接把所有用户数据集合脱敏后进入API 要得出整个终端设备用户数据的集体化建议 然后上报给边客户端（带有数据变化趋势以及集体化建议） 无网情况下同样也是由本地小模型处理脱敏用户数据集分析数据趋势并提供建议（低精度）然后上报
HyperVisor主要作用为数据过滤+模型处理+上报user-side和server-side
