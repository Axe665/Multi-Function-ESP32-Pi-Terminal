## 1. 本次修复的三个致命问题（按发现顺序）

### 1.1 GLIBC_2.38 不兼容
宿主交叉 gcc 的 `/usr/aarch64-linux-gnu/{include,lib}`（glibc 2.39）排在 sysroot（2.36）之前：
头文件侧让 C++ 引用 `__isoc23_*`；库侧让链接记录 `GLIBC_2.38` 版本需求。
→ 链接规则加 `-L sysroot/usr/lib/aarch64-linux-gnu -L sysroot/lib/aarch64-linux-gnu`
（libc/libm 提前）+ 注入 `work/compat/isoc23_compat.o`（7 个 `__isoc23_*` → 2.36 同名函数）。
**结果：全部 ELF 最高需求 ≤ GLIBC_2.35。**

### 1.2 缺 xcb 平台插件
原 Qt 构建 `FEATURE_xcb=OFF`（sysroot 只有 xcb 扩展 `.so.0`，无 `.so`；缺 `xkbcommon-x11`、
`xproto.pc`、`pthread-stubs.pc`）。
→ 从 Debian 12 arm64 仓库补 12 个 dev 包到 sysroot；另建 `qt653-build-xcb`（仅 qtbase）
启用 `-xcb`，编出 `libqxcb.so` + `libQt6XcbQpa.so.6.5.3`。

### 1.3 libQt6Gui 缺 QX11Application typeinfo + 缺 xcb EGL 集成
旧 Gui 在 xcb 关闭时构建，没有 `QNativeInterface::QX11Application` 的 typeinfo，
xcb 插件加载时报 `undefined symbol: _ZTIN16QNativeInterface15QX11ApplicationE`。
→ 用 `qt653-build-xcb` 的 Gui 替换（已验证：包含旧 Gui 全部 100% 符号，二进制差集为 0）；
并把 `libqxcb-egl-integration.so` 装到 `plugins/xcbglintegrations/`，否则
`QXcbIntegration: Cannot create platform OpenGL context, neither GLX nor EGL are enabled`。

## 2. 安装（Pi 上）

```bash
sudo tar -xf orpi-qt653-pi3.tar.zst -C /tmp     # GNU tar 1.34 自动识别 zstd
sudo mkdir -p /opt/qt653-arm64
sudo cp -a /tmp/orpi-qt653-pi3/opt/qt653-arm64/. /opt/qt653-arm64/
sudo cp -a /tmp/orpi-qt653-pi3/usr/. /usr/
sudo chmod 755 /usr/bin/{orange_pi_terminal,network_proxy,orange-pi-file-daemon,terminal_kdf_worker,terminal_flite_zh}
```
或直接用包内 `deploy-pi.sh`（会自动停服务、装完恢复服务）：
```bash
sudo bash deploy-pi.sh
```

## 7. Pi 上的自启 / 全屏 / 旧版替换（2026-11-04 18:10 完成）

### 7.1 旧版替换
- `/usr/bin/orange_pi_terminal` 等已由 v4 包覆盖为新版（Qt 6.5.3）。
- 旧版备份保留在 `~/.local/opt/orange-pi-terminal/20261018.bak-20261104/`（回退用）；
  指向它的 `current` 符号链接已删除，旧 `20-ble-hotspot-profile.conf`、
  `90-full-runtime-20261018.conf` 两个 drop-in 已删除，配置中不再引用旧版路径。

### 7.2 开机自启
沿用原有机制，无需新增服务：
- `~/.config/autostart/modular-terminal.desktop` → `systemctl --user start pi-module-terminal.service`
- 用户服务 `~/.config/systemd/user/pi-module-terminal.service`
- 生效 drop-in：`pi-module-terminal.service.d/99-exec-usr-bin.conf`

```ini
[Service]
ExecStartPre=-/usr/bin/nmcli con up pi-module-ap
ExecStart=
ExecStart=/usr/bin/orange_pi_terminal --config /home/raspberrypi/pi_debug/complex_qml_20261009/product-ble-hotspot-live-20261012.json --demo
Restart=on-failure
RestartSec=5
UnsetEnvironment=QTWEBENGINE_DISABLE_SANDBOX
```

### 7.3 默认全屏
`TerminalRuntime.cpp` 的逻辑：不传 `--window-size` 就 `window->showFullScreen()`。
因此 drop-in 的 ExecStart 特意**不传** `--window-size`。
实测窗口几何 `1024x600+0+0`，与屏幕 `1024x600` 完全一致。

### 7.4 沙箱恢复
原 unit 有 `Environment=QTWEBENGINE_DISABLE_SANDBOX=1`（关闭 Chromium 沙箱）。
drop-in 用 `UnsetEnvironment=QTWEBENGINE_DISABLE_SANDBOX` 移除；实测应用进程环境已无该变量，
`QtWebEngineProcess` 无 `--no-sandbox`。
