## 3. 本次遇到并解决的两个新问题

### 3.1 符号链接导致 Chromium 脚本路径穿越

`generate_shim_headers.py` 用 `os.makedirs(gen/../../.../home)` 时，因为 `/home/yuanzingo/qt653-{src,build}`
是符号链接，内核把 `..` 解析到链接目标一侧，最终落到 `/home`，报 `PermissionError`。
→ 改为 **bind mount**，路径成为真实目录层级，问题消失。

### 3.2 glibc 2.39 头文件 vs Pi glibc 2.36（`__isoc23_*`）

宿主交叉 gcc 的内置 include `/usr/aarch64-linux-gnu/include`（glibc 2.39）排在 sysroot（2.36）之前，
`-I sysroot/usr/include` 会被 GCC 判为"重复系统目录"而忽略。结果部分 C++ 目标引用
`__isoc23_strtol/sscanf/...`，链接 Pi 的 2.36 libc 时 `undefined reference`。
→ 写了 `work/compat/isoc23_compat.c`（7 个映射到 2.36 同名函数的桩），编译成 aarch64 .o，
  - 注入 `qt653-build/CMakeFiles/rules.ninja` 的 `CXX_SHARED_LIBRARY_LINKER__WebEngineCore_Release` 规则；
  - 注入 `qt653-build/qtwebengine/src/core/Release/aarch64/toolchain.ninja` 的两条 `rspfile_content`；
  - 注入项目 toolchain 的 `CMAKE_{EXE,SHARED,MODULE}_LINKER_FLAGS_INIT`。
验证：`libQt6WebEngineCore.so.6.5.3` 链接成功（198MB），`orange_pi_terminal` 未定义 isoc23 符号数为 0。

## 部署阶段新发现的三个问题

### A. GLIBC_2.38（v1→v2）
Qt 库误链宿主 glibc 2.39，Pi 2.36 上 `version GLIBC_2.38 not found`。
修复：链接规则加 sysroot `-L` + `isoc23_compat.o` 桩。详见主文档 3.2 与部署说明 1.1。

### B. 缺 xcb 平台插件（v2→v3）
`FEATURE_xcb=OFF`，Pi 是 X11 无法启动。
修复：sysroot 补 12 个 Debian arm64 dev 包（xcb 扩展 `.so`、`xkbcommon-x11`、`xproto.pc`、
`pthread-stubs.pc`），另建 `qt653-build-xcb`（仅 qtbase）启用 `-xcb` 编出 `libqxcb.so` +
`libQt6XcbQpa.so.6.5.3`。**不动主构建树**，避免 Chromium 重编。

### C. Gui 缺 QX11Application typeinfo / 缺 EGL 集成（v3→v4）
- 旧 `libQt6Gui` 没有 `QNativeInterface::QX11Application` 的 typeinfo，xcb 插件加载报
  `undefined symbol: _ZTIN16QNativeInterface15QX11ApplicationE`。
  用 xcb 构建的 Gui 替换（符号差集为 0，完全兼容）。
- 只补 xcb 插件仍报 `Cannot create platform OpenGL context, neither GLX nor EGL are enabled`，
  因为 `libqxcb-egl-integration.so` 没装到 `plugins/xcbglintegrations/`。补装后 OpenGL 告警消失。
